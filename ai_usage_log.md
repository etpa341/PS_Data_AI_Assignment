# AI usage log

An honest record of how AI was used. This is a starter; it is updated as the work goes on.

## Tools

- **Coding agent:** Claude Code (Claude Opus) wrote the profiling, pipeline, tests and notebook scaffold. I set the rules, made the decisions and checked the output.
- **In the solution:** an LLM classifies comment themes and sentiment (03_label.py). Model and settings are in `config/settings.yaml`. Labels are cached and measured against my hand labels (04_evaluate.py).

## What I delegated, and how I checked it

| Step | Delegated to the agent | How it was checked |
|---|---|---|
| Profiling (profiling/profile.py) | Read all 52 files and every sheet; write the Manifest, Issues_Log and Decisions_Log | Independent pandas checks of key findings (duplicates, the Penrith copy, the Chermside subset, Geelong inversion, Liverpool date order); built-in QA checks; totals reconcile |
| Decisions D1-D8 | Drafting the text and computing evidence from the data | I chose every decision; the evidence is recomputed on each run; checks that every decision links to an existing issue |
| Bronze / silver | Config-driven loading, cleaning, redaction | Bronze reconciles to the profiling Manifest (7,271 = 7,271); 12 silver self-checks; a rule log with rows checked and failed |
| Labelling pipeline | 03-05 scripts and tests with a fake client | 11 pytest tests (schema, one retry, cache hits, prompt-drift stop, metrics on dummy data, gaps missing not zero); no API calls during the build |

## Where the AI was wrong, or the first answer needed correcting

- **Dealer matching:** the first version matched Springwood to Ringwood (one name contains the other). Fixed with a longest-match rule.
- **Header detection:** comment rows in CSVs were taken for headers, and a merged banner row in Ballarat looked like a template change. Fixed.
- **Inversion check:** a false positive on a small Dandenong tab. Tightened to at least 8 comments each side and a gap of at least 0.5.
- **Record-ID collision metric:** first reported 163, then 76 copied comments; the real number was 0. Found with an independent pandas check.
- **Staff paraphrase tag:** the first regex tagged first-person comments ("Sarcastic as I am...", "Customer service was...") as staff write-ups. A spot check found every match outside Essendon and Ipswich was wrong, so the rule was tightened. The tag is still checked against my Voice_check labels.
- **Weak evidence:** keyword evidence for Bendigo "S" = Sales (D3) and for the Essendon duplicates (D6) was weak, so both decisions rest on a hand review, stated as one reviewer's judgement.
- **Model id (agent error, corrected):** the agent said SPEC.md's `claude-haiku-5-5` was not a published model and swapped in `claude-haiku-4-5-20251001` from its training knowledge. The pricing page (https://platform.claude.com/docs/en/about-claude/pricing, checked 2026-10-27) lists Claude Haiku 5.5, so the claim was wrong. Rule since then: the model is not assumed; `select_model.py` lists the models available to the API key and picks the newest Haiku, recorded below.
- **Environment:** opening a source CSV in Excel re-saved it with different date formats. Caught because the issue counts changed between runs; the original file was restored.

## Checks on analysis findings

- **Q2 rise (18.9% to 24.4%, like-for-like).** The first naive interval treated every response as independent. On my instruction the agent re-tested it: excluding Ringwood, dealer-clustered bootstrap, leave-one-dealer-out. The rise survives (clustered CI +1.0 to +10.6 pts), but Parramatta and Dandenong account for +3.3 of the +5.5 pts.
- **Collection-change check (Parramatta, Dandenong; before vs after May 2026).** The agent noticed that Parramatta's files gain a Booking ref column in May 2026; I asked for a before/after check at both dealers. Evidence found in the data (analysis.ipynb, `outputs/q2_collection_check.csv`):
  - Dandenong's May tab has a banner note: "new online booking system went live 5 May. Expect some teething issues - log everything!"
  - Dissatisfied comments mentioning the booking system rise to about a fifth at both dealers (others: about 3%).
  - Dandenong: volume +18% per 1,000 transactions and the extra responses are almost all dissatisfied → **suspected partly a collection change** ("log everything") on top of real booking problems.
  - Parramatta: volume about flat, fill rates, department mix and comment rate stable, and satisfied responses fall → **looks like a real change**.
  - Without both dealers, the group rise is +2.4 pts with a clustered CI of -0.5 to +5.7, so it is not a group-wide trend.
  - Still to confirm with both dealers: go-live dates and how feedback was logged after May.
- **Redaction gap seen in this check:** a staff first name that is not in any staff column (name withheld) appears in a redacted comment. The staff-name list only covers dealers with a staff column, as recorded in the silver rule log.

## Key prompts and interactions

I used two AI roles. Claude Code wrote and ran the pipeline in my repo. A separate Claude chat acted as advisor and reviewer: it critiqued my plans and prompts for Claude Code and drafted the report text, which I edited. I made the decisions.

1. **Spec before code.** I told the AI not to write any pipeline code until a spec was agreed. The spec (`SPEC.md`) fixed the bronze, silver and gold layers, the score scale, the eight themes and the dollar method first. Checked: I read the spec and chose between the options it raised (theme list, model, leave rates of 5%, 10% and 20%) before any build started.
2. **Profiling first.** I created a prompt to give Claude Code that profiled all 52 files before any cleaning. It produced an issue log of 158 issues at first, 161 after later checks and a list of open questions. Checked: I resolved the contradictions between the decisions it proposed (D1 to D5) and had them applied before building.
3. **Theme definitions and hand labels.** I labelled 120 comments blind, with the rating hidden, and edited the theme definitions as I went. `prompts/classify_v1.txt` was built from my edited definitions, so the model was judged against the same rules I used. I declined to let the AI label comments for me, because it would have measured the AI against itself.
4. **Classification prompt v1.** The model sees the comment text only and never the rating. Output is JSON checked against a schema. The prompt was never edited after evaluation. Checked: accuracy against my labels (sentiment 96.7%, theme 85.8%), a voice check of 30 rows, and a blind check of the 14 Vehicle and 20 Other comments.
5. **Redaction gap.** Counting unlisted staff names for the report exposed a bug: the redaction match was case-sensitive and the check used the same pattern, so it agreed with itself. 152 comments reached the model with a staff first name. Fix: case-insensitive match and an independent check that shares no code with the redaction. I authorised the relabel (152 calls, $0.037).
6. **Disagreeing with the AI.** Claude Code said the model I specified did not exist. I had the pricing page checked and it did, so the claim was corrected in this log. It also reported colliding record IDs (163, then 76) that an independent check showed were 0.
